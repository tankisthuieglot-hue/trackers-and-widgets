# vladislav — пак визуальных трекеров для SillyTavern

**Дата:** 2026-07-26
**Статус:** дизайн утверждён, каталог трекеров набирается отдельно

## Что это

Самодостаточный пак «маркер → виджет» для SillyTavern. Модель выводит короткий
текстовый маркер, регекс подменяет его на HTML-виджет **только при отображении**.
Ставится поверх любого пресета, не конфликтует с другими паками.

Публикуется на GitHub как отдельный проект.

## Мотивация

Существующие паки (MiNtorika MODERN и аналоги) доказали, что подход работает:
маркер стоит десятки токенов, виджет — ноль. Но у них две системные слабости:

1. **Хрупкий разбор.** Регекс — жёсткая цепочка полей по порядку. Модель
   переставила поля, пропустила одно или добавила лишнее → маркер не матчится →
   в чат вываливается сырой `[[NOTES|T=...|D=...]]`. Лечится это правилами в
   промпте («NEVER change the order... nor delete or add»), то есть за счёт
   токенов и свободы модели.
2. **Маркеры копятся в контексте.** Regex `markdownOnly` не трогает сохранённое
   сообщение, а чистка `promptOnly` вырезает только HTML-теги. Сами `[[...]]`
   остаются в истории навсегда.

vladislav закрывает обе.

## Область

**В работе:** контракт маркера, сборка исходников, валидатор, превью-стенд,
служебные регексы, документация, формат публикации.

**Отдельно:** конкретный каталог трекеров. Список и тематику задаёт автор пака
после утверждения этой спеки. Спека описывает фабрику, а не изделия.

**Не делаем:** Shadow DOM, собственный рантайм, поддержку не-ST фронтендов,
локализацию, CI.

## Контракт маркера

Неймспейс `VLD_` в тегах, `vld-` в CSS-классах. Без него `[[NOTES]]` из двух
разных паков подерётся, если пользователь держит оба.

```
[[VLD_NOTES|T=Заметка на день|D=11 мая|I1=Забрать заказ|F=Мелкие дела давят.]]
```

Правила для модели:

- один маркер на строке, не внутри прозы;
- значения без `|` и `]`;
- максимум один экземпляр одного маркера на ответ.

Порядок полей и их полнота **не регламентируются** — это обеспечивает грамматика.

### Грамматика разбора

Каждое поле ищется независимым lookahead'ом:

```js
const field = (k) => `(?=[^\\]]*\\|\\s*${k}\\s*=[ \\t]*([^|\\]]*)|)`;
const marker = (tag, keys) =>
  new RegExp(`\\[\\[${tag}${keys.map(field).join('')}[^\\]]*\\]\\]`, 'g');
```

Пустая альтернатива `|)` внутри lookahead обязательна. Очевидная запись
`(?=...)?` не работает: по спецификации ECMAScript RepeatMatcher прерывает
итерацию, если тело квантификатора совпало пустой строкой и не сдвинуло позицию,
после чего захваты сбрасываются. Ассерция всегда нулевой ширины, поэтому
`(?=X)?` в JS никогда не отдаёт захваченные группы.

Lookahead нулевой ширины, поэтому каждое поле сканирует маркер с одной и той же
позиции и находит свой ключ независимо от чужих. Класс `[^\]]` не пересекает `]`,
поэтому поиск не выходит за границы своего маркера. Замыкающий `[^\]]*\]\]`
съедает остаток.

Проверенное поведение (`node`, см. историю разработки):

| Вход | Результат |
|---|---|
| Поля в объявленном порядке | все захвачены |
| Поля в обратном порядке | все захвачены |
| Часть полей отсутствует | пустые строки, виджет цел |
| Неизвестное поле между известными | игнорируется |
| Перенос строки после `\|` | поле захвачено |
| Ключи-префиксы (`T`, `TM`, `T1`) | не путаются: разделяет `=` |
| Голый `[[VLD_HDR]]` | пустой каркас без ошибок |
| `$` в значении | сохраняется |

### Побочный эффект

Из промпта каждого трекера уходят правила про порядок и полноту полей. Трекер
становится короче, модель — свободнее, вероятность разрушения виджета падает
до нуля.

## Пайплайн

| Слой | Механизм | Цена в токенах |
|---|---|---|
| Маркер | промпт-блок в пресете, `role: system` | 40–80 на трекер |
| Рендер | regex `markdownOnly: true`, `placement: [2]` | **0** |
| Гигиена | regex `promptOnly: true`, `minDepth: 0` | 0 |
| Забывание | regex `promptOnly: true`, `minDepth: N` | 0 |
| Страховка | regex `markdownOnly: true`, последний в списке | 0 |

`markdownOnly` меняет только отображение — в сохранённом сообщении остаётся
сырой маркер, HTML в API не уходит вообще.

Порядок исполнения в SillyTavern — порядок скриптов в списке. Отсюда числовые
префиксы в именах: пользователь импортирует файлы по алфавиту и получает
правильный порядок.

### Служебные скрипты

- `00 PERF` — IntersectionObserver по классу `.vld-w`, глушит анимации за
  пределами экрана. Иначе двадцать виджетов в длинном чате роняют прокрутку.
- `01 CLEAN COMMENTS` — вырезает `<!-- -->` из исходящего промпта.
- `02 CLEAN STYLE` — вырезает `<style>...</style>`.
- `03 CLEAN SCRIPT` — вырезает `<script>...</script>`.
  Три чистильщика защищают от HTML, который модель сгенерировала сама;
  виджеты в промпт и так не попадают.
- `04 FORGET` — `promptOnly`, `minDepth: 5`: вырезает сами маркеры `[[VLD_*]]`
  из сообщений глубже пяти. Свежие пять модель видит для непрерывности сцены,
  дальше контекст чистый. Глубина настраивается пользователем в самом скрипте.
- `99 FALLBACK` — `markdownOnly`, последний в списке: `\[\[VLD_[A-Z0-9_]*[^\]\n]*\]{0,2}`
  → пустая строка. Всё, что дошло сюда, не совпало ни с одним виджетом, то есть
  сломано: незакрытые скобки, опечатка в имени тега, выдуманный трекер. Прячем.
  Пользователь не видит сырого текста никогда.

## Исходники и сборка

Виджет внутри JSON — это одна строка с экранированными `\n` и `\"`. Править
невозможно, дифф в гите нечитаем, превью недоступно. Поэтому исходник и артефакт
разделены.

```
src/notes/
  tracker.json    имя, тег, поля, WHEN/DON'T, пример
  widget.html     разметка с $1 $2 $3
  widget.css
  widget.js
```

`npm run build` собирает:

```
dist/regex/10-vld-notes.json    импорт в SillyTavern
dist/prompts.md                 блоки для вставки в пресет
```

Регекс и промпт генерируются из одного `tracker.json`. Рассинхрон между тем, что
обещает промпт, и тем, что ловит регекс, становится невозможен по построению —
это главная причина существования сборки.

### tracker.json

```json
{
  "tag": "VLD_NOTES",
  "title": "📝 NOTES",
  "order": 10,
  "when": "заметка, чеклист, напоминание — когда влияет на сцену",
  "dont": "как украшение без давления контекста",
  "fields": [
    { "key": "T",  "desc": "короткий заголовок" },
    { "key": "D",  "desc": "дата или день" },
    { "key": "I1", "desc": "пункт чеклиста" },
    { "key": "F",  "desc": "одна строка настроения" }
  ],
  "example": {
    "T": "Заметка на день",
    "D": "11 мая",
    "I1": "Забрать заказ до 21:00",
    "F": "Мелкие дела давят сильнее большой драмы."
  }
}
```

### Формат промпт-блока

```
<vld:notes>
FIRE: заметка, чеклист, напоминание — когда влияет на сцену
SKIP: как украшение без давления контекста

[[VLD_NOTES|T=|D=|I1=|F=]]

T короткий заголовок · D дата или день · I1 пункт чеклиста · F одна строка настроения

→ [[VLD_NOTES|T=Заметка на день|D=11 мая|I1=Забрать заказ до 21:00|F=Мелкие дела давят сильнее большой драмы.]]
</vld:notes>
```

Вставляется в пресет как промпт с `role: system`.

## Валидатор

`npm run check` — падает со внятной ошибкой, если:

- число полей в `tracker.json` ≠ число `$n` в `widget.html`;
- в `widget.html` есть `$n` с номером больше числа полей;
- в значениях `example` встречается `|` или `]`;
- собранный из `example` маркер не матчится собранным регексом и не даёт
  ожидаемых значений (сквозная проверка на реальном движке);
- CSS-селектор не начинается с `.vld-`;
- корень виджета не несёт класс `vld-w`;
- тег не начинается с `VLD_` или дублирует существующий;
- ключи полей не уникальны в пределах трекера.

Это ровно тот список поломок, на которых такие паки и ломаются в проде.

## Превью-стенд

`preview/index.html` — статическая страница, открывается двойным кликом.
Рендерит все виджеты на данных из `example`, переключает светлую и тёмную тему
и ширину под мобильный экран.

Позволяет доводить CSS без перезапуска SillyTavern и без единого запроса к
модели. Оттуда же снимаются скриншоты для README.

## Требования к пользователю

- SillyTavern.
- Расширение <https://github.com/MiNtorikaSoul/SillyTavern-JS-support> — включает
  выполнение JavaScript внутри сообщений. Без него виджеты отрисуются
  (HTML и CSS работают), но интерактив — чекбоксы, тапы, раскрытие блоков —
  работать не будет.

## Что скачивает пользователь

Только `dist/`:

- папка регексов — импорт в SillyTavern по одному файлу, порядок по именам;
- `prompts.md` — блоки копируются в пресет.

Плюс `INSTALL.md` с требованиями и порядком установки.

## Происхождение

Идея слоёного подхода — маркер, display-only регекс, чистка контекста по
глубине — взята из паков SillyTavern, прежде всего MODERN by MiNtorika. Это
способ, которым SillyTavern работает в принципе, а не чья-то собственность.

Весь код пака — грамматика разбора, вёрстка, стили, скрипты, тексты промптов,
сборка — пишется с нуля. Ничего не копируется дословно. В README указывается,
чем вдохновлён проект.

## Порядок работ

1. Каркас репозитория, `package.json`, лицензия.
2. `tools/build.mjs` и `tools/check.mjs` — фабрика раньше изделий.
3. Служебные регексы `00`–`04` и `99`.
4. Один эталонный трекер целиком, от `tracker.json` до превью.
5. Превью-стенд.
6. Остальной каталог — по списку автора.
7. README со скриншотами со стенда.

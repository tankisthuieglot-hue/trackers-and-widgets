# Как сделать трекер

Скопируй `src/demo/`, переименуй папку — имя папки становится CSS-классом
(`src/wallet/` → `.vld-wallet`).

```
src/wallet/
  tracker.json    что модель пишет
  widget.html     что видит читатель
  widget.css      как это выглядит
  widget.js       необязательно — интерактив
```

Дальше `npm run check && npm run build`, и `npm run preview` чтобы посмотреть.

## tracker.json

```json
{
  "tag": "VLD_WALLET",
  "title": "💳 VLD WALLET",
  "order": 11,
  "when": "деньги, оплата, долг, подозрительное списание",
  "dont": "каждая мелкая трата",
  "fields": [
    { "key": "T", "desc": "название карты или приложения" },
    { "key": "B", "desc": "баланс" }
  ],
  "example": { "T": "Т-Банк Black", "B": "18 742 ₽" }
}
```

| Поле | Зачем |
|---|---|
| `tag` | `VLD_` + заглавные. Уникален в паке. |
| `order` | 10–98, определяет порядок импорта. 00–04 и 99 заняты служебными. |
| `when` | попадает в промпт как `FIRE:` — когда маркер уместен |
| `dont` | попадает как `SKIP:` — когда нет. Необязательно, но почти всегда полезно. |
| `fields` | порядок полей задаёт номера `$1`, `$2`, … в разметке |
| `type` | у поля. `"num"` — грамматика возьмёт только цифры. Обязателен, если значение подставляется в HTML-атрибут. |
| `example` | эталон для модели и данные для превью. Должен быть заполнен целиком. |

Порядок полей в `fields` определяет только нумерацию `$n`. Модель может
выводить поля в любом порядке и пропускать любые — грамматика это переживёт.

## widget.html

Только внутренности. Корневой `<div class="vld-w vld-wallet">` добавляет сборка —
так гарантируется, что виджет попадёт под наблюдение скрипта производительности
и под свои же стили.

Поля подставляются как `$1`, `$2` по порядку из `fields`. Каждое поле должно
быть использовано хотя бы раз, иначе `npm run check` откажется собирать: поле,
которое просят у модели и выбрасывают, — это оплаченные токены в никуда.

### Значение в атрибуте

Число можно превратить в класс и рисовать по нему без единой строчки
JavaScript:

```html
<span class="strip lv-$4"><i></i><i></i><i></i></span>
```

```css
.vld-hud .lv-1 i:nth-child(-n+1),
.vld-hud .lv-2 i:nth-child(-n+2) { background: var(--fill); }
```

Модель прислала `2` — загорятся два деления. Прислала чушь — не совпадёт ни
одно правило, шкала останется пустой, вёрстка целой.

Поле, которое так используется, обязано быть `"type": "num"`. Иначе кавычка в
значении закроет атрибут и всё, что дальше, станет разметкой. `npm run check`
не даст собрать пак без этого.

### Модель что-то пропустила

Ничего делать не нужно, но проверь, как это выглядит. Пустое поле даёт пустую
строку — прячь её через `:has()`:

```css
.vld-hud .entry:has(.v:empty) { display: none; }
```

Лишние поля, которых нет в контракте, грамматика игнорирует молча. Если модель
выдаст четыре предмета там, где ты ждал три, — четвёртый просто не отрисуется,
а не сломает вёрстку. Когда количество принципиально не ограничено (инвентарь,
список треков), бери одно поле с перечислением через запятую вместо слотов.

## widget.css

Каждый селектор обязан содержать `.vld-<имя>`. Проверяется автоматически.

```css
.vld-wallet { }            /* да */
.vld-wallet .card { }      /* да — самая безопасная форма */
.vld-wallet.compact { }    /* да */
.card { }                  /* нет: заденет чужую разметку в чате */
```

Внутренние элементы называй коротко (`.card`, `.head`) и доставай через потомка.
Префиксовать их не надо — предок уже всё ограничил.

Единственное, что проверка не ловит: `.vld-wallet + div` заденет соседа виджета.
Соседские комбинаторы применяй только внутри виджета.

Цвета фиксированные. Виджет — это предмет, лежащий на странице, а не элемент
интерфейса, который следует за темой: у него свой непрозрачный фон, и он
выглядит одинаково у всех. Под тему SillyTavern не подстраиваемся — CSS её
всё равно не видит.

Отсюда одно требование: виджет должен читаться на любой подложке. Превью
показывает его сразу на светлом и тёмном фоне — если на одном из них он
пропадает, нужен фон поплотнее или контур.

## widget.js

Необязателен. Тело функции, в котором уже есть `root` — корневой элемент
виджета. Сборка сама оборачивает его и защищает от повторного запуска, так что
писать `if (initialized) return` не нужно.

```js
root.querySelectorAll('.item').forEach(function (item) {
  item.addEventListener('click', function () {
    item.classList.toggle('done');
  });
});
```

Работает только с расширением
[SillyTavern-JS-support](https://github.com/MiNtorikaSoul/SillyTavern-JS-support).
Без него разметка и стили отрисуются, а интерактив — нет. Поэтому виджет должен
быть осмысленным и без JavaScript.

Скрипт выполняется один раз на каждый виджет в чате, а виджетов в длинной
переписке накапливается много. Не вешай таймеры и не трогай ничего за пределами
`root`.

## Что проверяет `npm run check`

- тег уникален и подходит под `VLD_[A-Z0-9_]+`
- `order` уникален и лежит в 10–98
- ключи полей уникальны и записаны как `T`, `D`, `I1`
- у каждого поля есть описание — оно уходит в промпт
- каждое поле использовано в разметке, и разметка не ссылается на несуществующее
- в примере нет `|`, `]` и переносов строки
- маркер, собранный из примера, разбирается собственным регексом обратно в те же
  значения — это единственная проверка, доказывающая, что промпт и регекс сходятся
- каждый селектор содержит класс трекера
